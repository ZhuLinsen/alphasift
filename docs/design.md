# 设计原则

## 1. 硬条件必须由代码执行

估值、流动性、涨跌幅、技术指标阈值等确定性条件全部由代码执行。不把可验证逻辑交给 LLM。

## 2. 默认规则必须可覆盖

系统可以提供开箱即用的默认评分曲线和风险阈值，但不能把市场风格假设写死在代码里。策略 YAML 可以通过 `scoring_profile`、`risk_profile`、`portfolio_profile` 和 `scorecard_profile` 覆盖默认行为。

## 3. 策略知识只维护一份

所有选股逻辑通过 `strategies/*.yaml` 的 `screening:` 段定义。不在代码中写死筛选条件。

## 4. 横向评分独立于单股诊断

`screen_score` 是选股专用的横向评分，不等于单股分析中的 `signal_score` 或 `sentiment_score`。

原因：
- 单股诊断分数为"这只票值不值得分析"设计，不是"全市场候选怎么比较"
- 直接复用会造成 L1/L2/L3 职责混叠

## 5. 排序层、风险层分开

alpha 排序和风险约束不揉成一个总分黑盒。风险覆盖层单独判定 veto/penalty。

## 6. LLM 只做软判断

LLM 负责：新闻语义理解、候选间相对排序、候选行业/主题标签、潜在催化、风险摘要、排序理由生成。
LLM 不负责：全市场初筛、数值阈值判断、精确技术指标计算。

## 7. 组合约束来自 LLM 但不交给 LLM 自由发挥

LLM 可以识别候选之间的行业/主题共性，并输出组合集中风险；如果候选自带 `industry/concepts/board_heat_score/board_heat_trend_score/board_heat_persistence_score/board_heat_cooling_score`，这些结构化字段会作为 LLM 判断锚点。代码层把 LLM 标签或结构化行业映射到行业风险桶，再转成可审计的 `portfolio_penalty`。例如银行、券商、保险同属金融风险桶。这样既利用 LLM 的语义归类能力，又避免让 LLM 直接决定硬性行业配额。

行业/概念/板块热度锚点优先来自本地 CSV/JSON/JSONL 映射文件，也可显式启用 AkShare 板块反查。默认不自动抓全市场板块，以免一次选股变成大量网络请求；只有在快照完全缺少行业时，才会用一次轻量的东财行业映射（3 次请求、缓存 7 天）补全基础行业标签。

## 8. A 股走专用链路，其他市场走统一注册表

A 股有 ST、涨跌停、东财行业等独有约定，继续走专门的多数据源链路。美股、港股、日本、韩国、台湾、印度由 `alphasift/markets.py` 注册表描述（币种、时区、Yahoo 区域、代码后缀、股票池市值下限），统一通过 Yahoo 筛选器获取快照。A 股专属规则（`exclude_st`、候选级新闻/公告/资金流、东财行业补全）只在 A 股生效；跨市场策略不使用与币种相关的绝对金额阈值。

另外，`行业缺失` 不能让组合分散静默失效：A 股快照缺行业时会自动补全，补全失败会在 `degradation` 中明确提示。

## 9. 优雅降级

- 全市场快照不可用 → 任务失败（fail-fast）
- 关键字段缺失 → 任务失败（不做模糊降级）
- 策略必需的日 K 增强单行失败 → 记录 degradation 并让该候选在日 K 硬筛中淘汰；全局日 K 增强不可运行才任务失败
- 可选日 K 增强失败 → 回退到快照评分并记录 degradation
- LLM 排序失败 → 回退到 screen_score 排序
- 可选 L3 后置分析器失败 → 当前任务失败或记录 degradation，取决于分析器是否为用户显式请求

## 10. 与外部分析系统解耦

alphasift 负责 L1（硬筛）和 L2（排序）。L3 是后置分析器框架，默认调用本地 scorecard；也可追加外部 DSA，或其他 HTTP 评分工具。

这里的 DSA 指外部项目 `daily_stock_analysis`：
- alphasift 负责全市场候选发现和排序
- daily_stock_analysis 负责单股深度分析
- 两者通过 `DSA_API_URL` 解耦部署

为控制成本，默认 scorecard 覆盖全部最终候选；DSA 只在最终入围候选的前 N 只上调用。DSA 不是全市场筛选的核心依赖，也不是唯一 L3 工具。

## 11. 选股必须可评估

一次选股运行必须能保存足够上下文，便于后续评估：

- 策略名与 `strategy_version`
- 数据源与降级记录
- L1/L2/L3 分数和风险字段
- 候选保存时价格

当前 T+N 评估用保存价与评估时最新快照价计算收益、胜率、缺失报价、交易成本扣减和突破/回踩形态后验标签。可选价格路径会额外估算最大回撤和最大浮盈。它是工程闭环，不是完整复权回测。

## 附：能力一览

- **三层漏斗**：L1 代码硬筛 → L2 LLM 排序 → L3 后置分析（可选、可插拔）
- **策略即 YAML**：所有选股逻辑通过 YAML 文件定义，不写死代码
- **默认规则可覆盖**：因子评分曲线、风险阈值、组合风险桶、scorecard 规则和事件偏好都有默认值，也可在策略 YAML 中用 profile 覆盖
- **多因子候选画像**：每只候选输出价值、流动性、动量、反转、活跃度、稳定性、市值、主题热度和热度趋势等因子分
- **LLM 结构化软判断**：LLM 只在候选池内做跨股票比较，输出全局市场判断、选择逻辑、组合风险、候选 thesis、行业/主题、风险、催化、标签和信心分；若快照或外部数据提供 `industry/concepts/board_heat_score/board_heat_trend_score`，会作为 LLM 判断锚点；`--candidate-context-file` 可按 `code` 对齐候选级新闻、公告、资金流或自定义研究摘要，抓取上下文会带来源数、来源置信度、来源权重分、公告类别、事件标签和负面风险标签
- **组合分散覆盖层**：LLM 标注行业/主题后，默认按行业风险桶对重复候选做温和扣分；若 LLM 缺失行业标签但候选有 `industry`，会用结构化行业作后备锚点
- **LiteLLM 配置复用**：兼容主模型、fallback、多渠道和 Router YAML，方便复用作者其他项目配置
- **独立风险层**：在 LLM 后对过热、弱信号、低置信度等风险做统一扣分或剔除
- **候选级日 K 增强**：只对 L1 后 Top N 候选补充 MA、60 日涨幅、MACD/RSI、signal_score、20 日突破幅度、区间振幅、20 日量能比、实体强度、MA20 回踩距离和平台持续天数；`DAILY_SOURCE=auto` 且配置了 Tushare token 时会先试 `tushare`，否则优先走 `tencent`、`sina` 直连源，再降级到 `akshare`、`baostock`；低质量、拉取失败或 stale cache 行会进入最终风险扣分
- **默认 L3 评分器**：本地 `scorecard` 默认启用，作为最终候选的轻量一致性复核
- **可评估闭环**：保存运行结果，用后续最新快照做 T+N 收益、胜率、缺失报价、交易成本扣减、等权组合摘要、形态后验标签和失败样本复盘；可选抓取日 K 路径计算最大回撤和最大浮盈
- **DSA 后置增强**：DSA 只是一种可追加 L3 分析器，不参与全市场初筛，也不是默认依赖
- **为 Agent 设计**：SKILL.md 描述能力和接口，任何支持 Skill 协议的 Agent 都能调用
