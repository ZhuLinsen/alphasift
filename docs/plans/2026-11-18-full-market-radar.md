# AlphaSift 升级终版方案（基于 carbon 方案修订）

基线：main@d5500c7，2026-11-18。已确认决策：先做深 A 股、其他市场不动；离线包用免费源 + TickPlus；接力谱系只做盘面统计不出信号；主仓战绩增加 AI 赛道。

## 0. 结论

方向成立：全市场日线矩阵 + 形态 + 可审计战绩，是 AlphaSift 相对 DSA 的真正增量。
但 carbon 方案有三类问题：把已有能力当新增、若干技术选型与实测不符、范围过大且缺少"上线门槛"。
终版把它收敛为 **4 个阶段、9 个 PR**，每个 PR 有可验收标准。

## 2. 对 carbon 方案的修正

### 2.1 数据包格式：npz，不用 Parquet

实测（腾讯日线 150 只 × 250 日，按 5400 只外推）：

| 格式 | 120 日 | 250 日 | 新增依赖 |
|---|---|---|---|
| Parquet + zstd | 14.5 MB | 30.3 MB | pyarrow，安装后 138 MB |
| csv.gz | 13.8 MB | 28.8 MB | 无 |
| npz（float32 矩阵） | 13.8 MB | 28.8 MB | 无 |

Parquet 没有体积优势，而 pyarrow 比要砍掉的 LiteLLM（57 MB）还重。
采用 **npz**：每个字段一个 `日期 × 代码` 矩阵，加载后就是向量化计算要的形状。
成交额列在样本里是用量价合成的，真实体积会略有出入。

### 2.2 窗口 250 日，不是 120 日

形态需要约 60 日预热，评估需要 T+10 前瞻。120 日只剩约 50 个可用信号日，不足以做上线前的胜率检验。
250 日约 29 MB，Release 资产无压力。

### 2.3 "免爬虫"只对下游成立，主仓构建链路要讲清

- **一次性回填**：baostock，`adjustflag=3` 不复权并带 `preclose`。现有 `daily.py` 用的是前复权（`adjustflag=2` / `qfq`），需新写不复权路径。
- **每日增量**：TickPlus `updatedaykline`，每个交易日 1 次调用返回全市场不复权日线和昨收 `pc`。该接口只支持最近一周，所以缺口超过一周时回落到 baostock 补洞。
- **兜底**：Actions 上实测唯一可用的快照源是 `em_datacenter`，但它当前只取现价、涨跌幅、成交额、估值、行业，没有开/高/低/昨收。能否扩字段**待验证**；不行则兜底只有"次日 baostock 补洞"。
- **元数据**：名称、行业、PE/PB、市值取自当日快照，存为 `meta.csv.gz`。

**阻塞项（需你确认）**：
1. TickPlus 免费版是 7 天试用、每日 100 次，长期运行需要付费档。
2. TickPlus 服务条款是否允许把数据放进公开 Release 再分发。不允许的话，增量源只能用免费源，TickPlus 仅做校验。
3. TickPlus 接口是 HTTP 且 token 在查询串里，日志必须脱敏。
4. GitHub 海外 runner 能否访问 `api.tickplus.org` 未验证。拿到 token 后先用手动触发的 workflow 测通；不通则打包这一步改由国内机器（自托管 runner 或定时任务）执行，其余流程不变。

### 2.4 用 manifest 判断新鲜度，不依赖 16:45 / 17:15

Actions 定时任务经常延迟，固定时刻不可靠。
- 主仓：打包与 track-record 放进同一 workflow，用 `needs` 串行。
- 下游：读 `manifest.json` 的 `trade_date`。不是当日则轮询等待（上限可配），仍没有则拉快照拼接，再失败就 fail-fast 并写入 `degradation`。
- manifest 含每个文件的 sha256、行数、代码数、构建源。

### 2.5 动态前复权：保留，但加校验

"昨收 ≠ 前一日收盘 → 按比例缩放历史"的做法正确，前提是昨收为交易所除权参考价。
验收：随机抽 50 只近一年有除权的股票，与前复权源逐日比对，误差小于 0.5%。

### 2.6 观察/确认不做持久化状态机

Actions 无状态，持久化状态机会带来落盘、幂等、重跑不一致问题。
改为**无状态回看**：确认 = 今日满足确认条件，且过去 N 日内出现过观察信号，且期间未跌破证伪位。全部从矩阵重算，重跑结果一致。

### 2.7 情绪周期：先当切片维度，不当权重

"冰点/启动/主升/分歧/退潮"是主观划分，直接用来调选股权重等于未经验证的过拟合，与 #34 的非目标一致。
- 先输出客观指标：涨跌停家数、封板率、昨涨停溢价、连板高度、上涨占比。
- 阶段标签由这些指标的规则给出，只进报告和评估切片。
- 当"形态 × 阶段"切片每格样本 ≥ 100 且差异稳定时，再开一个 PR 让它影响权重。

### 2.8 形态首批 6 个，且有上线门槛

| 谱系 | 首批 | 说明 |
|---|---|---|
| 底部反转 | 底部倍量阳、双底突破 | |
| 趋势中继 | 20 日线缩量回踩、单阳不破 | 回踩与现有 `shrink_pullback` 对齐 |
| 强势突破 | 箱体突破、仙人指路确认 | 突破与现有 `volume_breakout` 对齐 |
| 短线接力 | 不出信号 | 只做连板梯队、封板率统计（已确认） |

上线门槛：在 250 日包上回放，T+1 开盘入场，样本 ≥ 200 且 T+5 相对基准超额 > 0，才进默认日报；否则标 `experimental`，只在看板展示。
幅度参数统一用 ATR 倍数或涨跌停幅度归一化（保留 carbon 的设计）。
"上方 10% 成交量占比"是筹码的粗略近似，作为特征输出并进切片验证，暂不做一票否决。

### 2.9 LiteLLM：移除

依据：
- **安全**：2026 年两次 PyPI 供应链事件。3 月的 1.82.7 / 1.82.8，10 月的 1.107.0（恶意 `.pth`，装了就执行，不需要 import）。
- 本仓 `litellm>=1.0` 未锁版本，`track-record.yml` 在 `contents: write` 的 job 里执行 `pip install -e .`，CI 直接暴露。
- **体积**：57 MB，12 个硬依赖（含 openai、tiktoken、tokenizers、aiohttp）。
- **用量**：只用了 `completion` 和 Router 做回退（`ranker.py:488-560, 802-861`）。
- 历史 issue #17、#20 都是"LLM 已降级"，少一层封装更容易定位。

关于"主流项目做法"：搜索没有拿到可引用的项目调研，这条建议基于上面的安全与用量事实，而不是基于同行统计。DeepSeek、Gemini、通义、智谱、Moonshot、Ollama、OpenRouter 都提供 OpenAI 兼容端点，是可行性前提。

做法：
- 用 `requests` 调 `/chat/completions`，约 150 行：内置网关表、多 key 轮换、按顺序回退、超时降级到纯规则。
- **保持兼容**：`*_API_KEY`、`LLM_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY`、`LLM_CHANNELS`、`LITELLM_MODEL`（`provider/model` 前缀映射到网关表）、`LITELLM_FALLBACK_MODELS`。
- **不再支持**：`LITELLM_CONFIG`（Router YAML）和原生 Anthropic 协议。检测到时报错并给出等价的 `LLM_CHANNELS` 写法。
- **不新增 URI 协议**（`ALPHASIFT_LLM_1=url#model=..&key=..`）：`LLM_CHANNELS` 已能表达同样内容，再造一套格式要多维护一套解析和文档，且密钥放在 URL 里容易进日志。
- 版本号升到 0.3.0，CHANGELOG 写迁移说明。

本机装的是 1.81.10，不在受影响版本内。

### 2.10 多模型委员会：推迟

成本乘 N，收益未证。先上单模型 AI 赛道进公开战绩，"规则榜 vs AI 榜"积累 ≥ 60 个交易日后再决定。

### 2.11 T+1 开盘入场：新增模式，不替换

- `entry_mode=next_open` 与现有收盘模式并存，已有 85 个 run 保持可比。
- 入场日开盘一字涨停：标 `untradable`，不计入胜率，单独统计占比。
- 退出日一字跌停：顺延到可卖出日。
- A 股的开盘价直接来自数据包，不增加抓取。

### 2.12 多市场

新能力只对 `cn` 生效，通过 `markets.py` 注册表加能力位控制。其他 6 个市场的路径零改动，现有测试作为回归保护。

### 2.13 Fork 体验

Fork 后定时 workflow 默认禁用，Pages 也要手动开启。"一键拥有"不成立，需要文档写清 3 步，并让 `alphasift doctor` 检查包可达性和推送配置。

## 3. 目标架构（A 股）

```
Release 资产 data-cn: daily.npz + meta.csv.gz + manifest.json
        │  pack.load() → 动态前复权 → 可选拼接当日快照
        ▼
日线矩阵（250 日 × 约 5400 只）
        ├─ 盘面统计：涨跌停、封板率、连板梯队、昨涨停溢价、阶段标签
        ├─ 向量化特征：与现有 daily 特征同口径
        └─ 形态信号：原子算子 + YAML 组合 + 无状态观察/确认
        ▼
现有链路：YAML 硬筛 → 评分 → 风险层 → 组合约束 →（可选）LLM 重排 → L3
        ▼
report.json ──► IM 卡片（<1200 字，幂等） / Pages 看板 / 保存 run → next_open 评估
```

没有包或加载失败时，自动回到现有"快照 + Top N 补日线"路径并记录 `degradation`。

### 执行方式

- 一次只做一个 PR，按该 PR 的验收标准收尾，合并后再开下一个。
- 可立即开工：P0-1、P0-2；P0-4 排在 P0-2 之后（A 股开盘价来自数据包）。
- 暂缓：P0-3，待 2.3 的阻塞项（付费档、再分发条款、runner 连通性）确认。
- 不需要自建服务端：打包在主仓 Actions 里完成，token 放 Secrets。

## 5. 明确不做

- 持久化状态机、URI 模型协议、Parquet、多模型委员会（本期）、接力选股信号、情绪阶段调权重（本期）。
- #34 里的非目标继续有效：不做交易执行、不做完整组合记账、不引入高封禁风险源、不做过拟合调参。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 行情数据公开再分发的授权（TickPlus 条款、交易所数据） | 先确认条款；Release 说明写明仅供研究；必要时只分发衍生特征而非原始行情 |
| baostock 回填约 5400 次请求，耗时长 | 只在首次和补洞时跑；分片并可断点续跑 |
| 向量化特征与旧口径不一致，导致策略表现漂移 | 一致性测试 + 战绩里标注切换日 |
| 形态样本不足却被解读为胜率 | 看板强制显示样本数，低于门槛置灰 |
| 0.3.0 破坏 `LITELLM_CONFIG` 用户 | 报错信息直接给出等价配置；CHANGELOG 置顶 |
